> Auto-generated from codebase analysis. Last updated: September 2026.

## Architecture Overview

The offline system uses a **dual-layer architecture**:

1. **SyncEngine** (`src/lib/sync/SyncEngine.ts`) — low-level: pushes outbox ops via `POST /api/sync`, pulls server changes by `updatedAt` cursor.
2. **OfflineSyncEngine** (`src/lib/offline/index.ts`) — wrapper: adds tenant-scoped cache keys (`tenant:collection`), `useCachedList` / `useCachedGlobals` hooks, and optimistic cache writes.

**Storage adapters:** SQLite (desktop/Tauri) and IndexedDB (browser). Both implement `StorageAdapter` with identical schema: outbox, cache, kv, idmap tables.

**Sync endpoint** (`src/app/api/sync/route.ts`):
- **Push:** accepts batch CRUD operations for `ALLOWED_COLLECTIONS`
- **Pull:** queries `updatedAt > lastSyncAt` for `changeCollections` (a subset of ALLOWED)

## Known Gaps & Recommended Work

### 🔴 Critical

1. **Expense Claims** — Users create claims offline but they vanish on reconnect. Add to `ALLOWED_COLLECTIONS` + `changeCollections`.
2. **Recurring Schedules** — Editing a schedule offline doesn't sync. Add push support at minimum.

### 🟡 Important

3. **Members pull** — Other users' member changes aren't seen until page refresh. Add `members` to `changeCollections`.
4. **Membership Types pull** — Same as above. Add to `changeCollections`.
5. **Billing Settings sync** — Changes from other users (e.g., new default accounts) aren't seen. Add a pull mechanism or real-time event.
6. **Doc Sequences** — Number generation must be server-authoritative, but the sequence cache could be stale causing duplicate numbers. Consider a server-side lock.

### 🟢 Nice to Have

7. **Bank Statements** — Large import data. Could add read-only pull for reconciliation.
8. **Audit Logs** — Append-only. Could add read-only pull for log browsing offline.
9. **Stock Transactions / Inventory Items** — Not yet in UI. Plan sync when these are built.

## Adding a New Collection to Sync

To make a new collection fully offline-capable:

### 1. Server: Add to sync route

```typescript
// src/app/api/sync/route.ts

// Add to ALLOWED_COLLECTIONS (for push):
const ALLOWED_COLLECTIONS = new Set([
  // ... existing
  'your-collection',
])

// Add to changeCollections (for pull):
const changeCollections = [
  // ... existing
  'your-collection',
]
```

### 2. Client: Use `immediate: true` or queue to outbox

```typescript
// For writes that should go directly to server:
await api('/your-collection', {
  method: 'POST',
  body: data,
  immediate: true,  // bypass outbox
})

// For writes that should queue offline:
await api('/your-collection', {
  method: 'POST',
  body: data,
  // no immediate → goes to outbox
})
```

### 3. Client: Use `useCachedList` for reads

```typescript
const { docs, loading } = useCachedList<YourType>('your-collection', {
  sort: '-updatedAt',
  ...tenantQuery,
})
```

### 4. Client: Add tenant scope (if applicable)

The `cacheKey` function in `SyncEngine` already handles tenant-scoped keys. The wrapper's `warmCache` and `readCollection` use `${tenant}:${collection}` keys automatically.
